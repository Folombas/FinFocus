🛠️ Про создание сайта на бесплатном хостинге GitHub Pages

Как FinFocus живёт без серверов, за какие деньги (спойлер: за ноль) и почему без бэкенда тут не то что можно, а нужно.

Что такое GitHub Pages и почему это бесплатно

GitHub Pages — это статический хостинг, встроенный прямо в репозиторий: кладёшь HTML, CSS и JS в ветку, включаешь Pages в настройках, и сайт доступен по адресу вида folombas.github.io/FinFocus. Платить не нужно, сервера администрировать не нужно, HTTPS включается галочкой.

Слово «статический» здесь ключевое: хостинг отдаёт файлы ровно в том виде, в каком они лежат в репозитории. Никакого кода на сервере не выполняется, и это не ограничение, а контракт: он заставляет сайт быть быстрым, простым и предсказуемым.

Вся мощь платформы, которую мы используем

  1. PWA и офлайн-режим. Манифест приложения плюс Service Worker с версионируемым кэшем: сайт устанавливается как приложение и открывается без интернета. При обрыве сети посетитель видит аккуратную страницу offline.html, а не ошибку браузера.
  2. Мгновенная навигация. Speculation Rules prefetch: браузер заранее скачивает страницы, на которые вы, скорее всего, нажмёте. Переход ощущается мгновенным.
  3. CI-конвейер на GitHub Actions. Каждый пуш проходит гейты: проверку синтаксиса, строгую проверку типов (tsc с DOM-библиотекой) и структурные проверки HTML. Сломать сайт неосторожным коммитом нельзя.
  4. Данные по расписанию. Отдельный workflow каждый день забирает курсы ЦБ из публичного фида и коммитит свежий JSON. Без ключей, без сервера, без платежей.
  5. Локальное хранение данных. Трекер накоплений в тренажёре работает на IndexedDB: записи живут прямо в браузере посетителя, с экспортом и импортом в JSON.
  6. Поиск без сервера. Поиск по сайту работает поверх статического JSON-индекса: страница поиска и файл данных, Elasticsearch не нужен.
  7. SEO-разметка. JSON-LD (schema.org) на главной, корректные canonical и Open Graph на каждой странице.

Переписали ли мы всё на TypeScript и фреймворки?

Нет, и это осознанное решение, а не недоделка. Код сайта остался нативным JavaScript без сборки и зависимостей, но мы добавили главное от TypeScript: строгую проверку типов. В проекте лежит tsconfig с DOM-библиотекой, типы описаны JSDoc-аннотациями, а CI запускает tsc --noEmit на каждый коммит. Получается «TypeScript без переписывания»: типы ловят ошибки, но билд-степа нет, и любую страницу можно править руками.

Фреймворки вроде React для сайта такого формата дали бы только минусы: обязательная сборка, тяжёлый бандл, хуже SEO и длиннее загрузка на слабых устройствах. Все современные возможности платформы (View Transitions, Speculation Rules, Service Worker, IndexedDB) доступны и без фреймворка.

А бэкенд? Честный ответ

Классический бэкенд на GitHub Pages прикрутить нельзя: серверный код (Node, PHP, Python) там не выполняется, баз данных и файлов на запись тоже нет. Но почти каждая задача бэкенда для такого сайта решается бесплатно и без него:

  • Хранение данных пользователя — IndexedDB и localStorage в браузере (так работает наш трекер накоплений).
  • Актуальные данные — GitHub Actions генерирует JSON по расписанию и коммитит его в репозиторий.
  • Формы и обратная связь — внешние бесплатные сервисы форм или GitHub Issues как комментарии.
  • Полноценный бэкенд с базой и авторизацией — внешний бесплатный тариф BaaS (Supabase, Firebase и подобные), с которых сайт обращается к API прямо из браузера.

Формула такая: всё, что можно посчитать и хранить на клиенте, живёт на клиенте; всё, что требует сервера, выносится на бесплатный внешний сервис; всё, что требует свежести, делает Actions. Для образовательного сайта этого хватает с запасом.

Как повторить в пяти шагах

  1. Создай публичный репозиторий и положи туда HTML с CSS и JS.
  2. Включи Pages в настройках: ветка main, корень. Сайт жив через минуту.
  3. Добавь веб-манифест и простой Service Worker: получишь установку и офлайн-режим.
  4. Положи tsconfig.json и включи tsc --noEmit в Actions: типы будут проверяться на каждый коммит.
  5. Добавь cron-workflow для данных и JSON-индекс для поиска. Бэкенд так и не понадобится.
Итог: бесплатный хостинг, установка на телефон, работа офлайн, автопроверки кода и свежие данные по расписанию. Статический контракт не урезает возможности, он дисциплинирует архитектуру.
